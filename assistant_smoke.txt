The loyalty event schema uses a stable event envelope to manage schema changes safely. The required fields in the event payload are:

- `event_id` (serves as the idempotency key)
- `event_timestamp` (in UTC ISO 8601 format)
- `event_type`
- `member_id` (synthetic, contains no personal information)

Additional fields typically included are:

- `event_version` (controls schema evolution)
- `partner_id`
- `transaction_id`
- `points` (may be positive for earning or negative for redemption/adjustment)
- `amount_aud`
- `channel`
- `source_system`
- `trace_id`
- `attributes` (for unknown or additional attributes, e.g., `campaign_id`)

Example payload:

```json
{
  "event_id": "ad23918c-127e-4863-a15a-c1bc4a62047e",
  "event_type": "POINTS_EARNED",
  "event_version": "1.0",
  "event_timestamp": "2026-08-20T09:15:31.251Z",
  "member_id": "M000123",
  "partner_id": "ACCOR",
  "transaction_id": "T-7dc8caf1",
  "points": 250,
  "amount_aud": 125.5,
  "channel": "MOBILE_APP",
  "source_system": "LOYALTY_SIMULATOR",
  "trace_id": "f7f709e8-d03f-44e9-9ae5-5b06c98784b0",
  "attributes": {
    "campaign_id": "WINTER_BONUS"
  }
}
```
